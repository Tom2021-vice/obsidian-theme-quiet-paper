# Quiet Paper · 静纸

以 Telari 文档排版为参考的 Obsidian 主题。暖白背景、白色纸面、中西文衬线正文，同时适配阅读视图与实时预览。

**0.1.1 为开发预览版。用户截图已确认首版的纸面与衬线观感；本版调整表格列宽、路径换行和编辑器样式范围，更新后的视觉与编辑交互仍待截图验证。**

## 手动安装

1. 解压 `Quiet-Paper-0.1.1.zip`，得到 `Quiet Paper` 文件夹。
2. 将整个文件夹复制到你选定仓库的 `.obsidian/themes/` 下。最终路径应是 `.obsidian/themes/Quiet Paper/theme.css` 和同目录的 `manifest.json`。
3. 在 Obsidian「设置 → 外观 → 主题」选择 **Quiet Paper**，基础配色选择浅色。
4. 正文字号设为 **18**，在编辑器设置中开启「缩减栏宽」。

从 0.1.0 更新时，手动替换该主题文件夹里的 `theme.css` 与 `manifest.json` 即可；不需要替换仓库配置或笔记。

主题可以独立使用，不需要安装社区插件。首版声明的最低应用版本为 1.13.7；更早版本尚未验证。

## 字体与参考效果

- 西文：已内嵌 TeX Gyre Pagella 的常规、粗体、斜体、粗斜体，离线可用。
- 中文：优先使用本机 **Noto Serif SC** 或 **Source Han Serif SC（思源宋体）**，缺少时回退到宋体。未将中文字体打包进主题。
- 公式：保留 Obsidian MathJax 的字体与排版。
- 代码：使用本机 Cascadia Code 或 Consolas 等宽字体。

要比较参考效果，建议暂时清空 Obsidian 外观设置中用户自定义的正文字体，让主题字体栈生效。你也可以保留自己的选择，但换行、字宽和观感会随字体变化。

字体候选尚未确认与 Telari 原图完全一致。当前两端对齐采用浏览器排版，没有实现 Telari 的 Knuth–Plass 全段断行。

## 对照样例

项目的 `demo-vault` 是一个独立演示库，可由你手动用 Obsidian 打开，也可以只把里面的笔记和 `assets` 文件夹复制到自己的测试库。

- `01 — A Quiet Argument.md`：与参考图对应的中英、多语言及公式样例。
- `02 — Markdown 元素.md`：标题、链接、列表、引用、Callout、代码、表格、图片与嵌入。
- `03 — 边界检查.md`：窄列、长链接、超宽公式、代码、表格和字体回退。

演示库预设字号 18、浅色、缩减栏宽、严格换行，并关闭重复的行内文件标题。复制笔记到已有库时，不要用演示库的 `.obsidian` 配置覆盖个人配置。

第一轮建议截图：同一份 `01` 笔记、同一窗口宽度，分别截阅读视图和实时预览。实时预览时将光标放到文末，以便比较正文排版；另截一张光标进入标题或公式后的编辑状态。请同时说明系统显示缩放、应用缩放与正文字号。

## 调整选项

已预留 Style Settings 设置声明。如你已经安装该插件，可在 **Quiet Paper · 静纸** 下调整正文宽度、中文字体、行高、纸面边距，或关闭阴影与两端对齐。该插件不是主题依赖，尚未进行插件面板实测。

不用插件时，可手动启用 CSS 片段：

```css
body {
  --qp-line-width: 40em;
  --qp-line-height: 1.6;
  --qp-paper-padding: 1.9em;
  --qp-cjk-font: "Noto Serif SC", "Source Han Serif SC", "SimSun";
}
```

默认纸面随单个面板宽度收缩；面板很窄时改为左对齐。源码模式保留等宽编辑。深色仅提供基础配色，不属于首版 1:1 验收目标。

0.1.1 的表格保留至少约 6 个正文字号的列宽；表格内的长代码路径允许视觉换行。列数过多时仍保留局部横向滚动。短表格按内容确定宽度并与正文左边缘对齐。

## 开发

需要 Node.js 22。日常构建不联网，也不启动 Obsidian。

```sh
npm ci
npm run check
```

修改 `src/*.css`，不要直接改生成的 `theme.css`。构建会同步项目根目录、`dist/Quiet Paper` 和演示库里的主题文件，不写入个人笔记库。

`scripts/fetch-fonts.py` 仅在更新字体时使用，需要 Python 的 fontTools 和 Brotli；现有字体已包含在源码中，普通构建无需运行它。

详细计划见 `PLAN.md`，验证状态见 `docs/VALIDATION.md`。
